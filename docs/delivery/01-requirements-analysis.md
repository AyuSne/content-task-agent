# 需求分析与题面覆盖

## 用户、目标与成功标准

本项目选做笔试**第2题：内容任务规划 Agent**。帮助运营人员在任务预算和方案截止时间内，为虚构剪辑 App「帧剪」准备并核实保存一份内容活动方案。

运营提供主题、预算、截止时间及可选的受众、创作要求。完成时交付活动方案、任务计划、步骤状态、实际工具结果、费用合计和保存事实；条件不足时保留已有成果，明确未完成状态与具体缺口。方案准备的模拟工具费用、真实模型用量和后续制作投放费用分别记录。

任务预算和方案截止按合成费用/耗时表及模拟业务时钟核对；真实API延迟另记，暂停期间模拟时钟保持原进度。

开发与评审人员通过CLI复现操作，并从输入、完整方案、执行报告、Trace和可执行测试核对结果。保存成功要求当前版本及全部交付文件已核实，生成草稿表示取得中间成果。

## 已实现的加分项与增强

题面加分项“失败步骤续跑”已支持跨进程恢复，延续原成果、消耗、模拟时钟和轮数。进一步实现业务简报、创作策略比较、独立有界核验与返修、素材证据关联、输入及产物版本、人工稿显式导入、保存未知核实和导出修复，以及真实校准与对照评估。增强能力的验收细节见两份验收报告，题号范围保持第2题。

## 工程与操作边界

- SQLite是任务权威状态，CLI是公开interface；真实与Mock的身份、数据库、输出及结论隔离。
- 新任务默认最多24轮，每轮一个动作，失败或非法响应也计数；已有任务沿用创建时记录的上限，历史12轮任务保持12轮。续跑不重置额度。
- 策略表默认v2供新任务采用；已建任务的查询、比较与执行按已记录策略版本加载。
- 资料中的操作性文字按资料处理；评估只有限回读本任务已有材料，新增资料和用户取舍由主任务处理。
- 本地密钥配置被忽略，提交产物保留配置说明和脱敏信息。模型API直连，不指定7890，保留TLS校验和零SDK自动重试。
- 界面、线上部署、多Agent平台及生产级Runtime均非题面必需。此项目未接真实发布或投放；模拟按时、核实保存和可继续制作分别解释，生产稳定性及真实营销收益尚无验证。

远程仓库、评审账号权限和考试平台提交按用户后续授权处理。
