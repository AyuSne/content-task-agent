# 设计与取舍

## 任务interface

以`run/resume`承载从合法输入到核实保存的完整行为；query/create重复请求不暗中执行。CLI返回任务状态、版本、当前缺口、分类资源与保存事实。`review/save`是明确的单步入口，完整验收由主Agent自主选择核验和保存。

## 集中规则

- `evaluation.evaluate`是一套有界核验implementation，三个调用方只保留实际不同的权限、记录和实验责任；无回读时不额外获得协议纠错机会。
- `save_preconditions`集中内容/版本/评审处置资格，资源重估与保存共同使用；文件观察导致的未知状态与实际重试分别处理。
- 模拟账本、真实模型用量和活动费用分开；请求与业务尝试均在外部执行前登记，中断不丢旧消耗，未知不猜成零。

## 版本与恢复

输入更新形成任务版本，生成/人工编辑形成产物版本；仅资源变化可留明确语义复用证明，旧稿形成依据不被改写。显式采用知识/资料时追加完整旧/新正文；普通重启使用任务冻结内容。

保存事务内投影最终状态生成报告/Trace，全部文件核实后提交。写文件前持久保存未知，预期OSError保留未完成；内部程序错误传播并回滚暂定完成。原成功尝试不因导出修复重新计时，原失败不因后来成功而消失。

主模型核验通过后比较保存和有收益改进，而非清空所有optional。批量处置减少无语义收益的API动作，每条仍有依据；非法项整批拒绝。默认24轮依据真实动作成本修订，不作为无限执行或必然成功的保证。

## 权限与呈现

检索材料中的指令只作数据；评估只读本任务材料，不能搜新资料、改稿或保存。运营稿与执行报告分开，均关联同一权威版本；导入显式关联基稿，过期基稿不覆盖。导出发现外部变更时保留用户文件，显式修复才重建。

本期保持SQLite、普通Markdown知识与原生循环，不做生产级分布式runtime、文件监视、自动合并、上下文压缩或跨任务学习。设计效果以[实际验收](10-repair-acceptance.md)为准。
