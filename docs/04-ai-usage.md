# AI 使用、个人贡献与实际投入

## 围绕 Context 与 Loop 组织开发

模型依据拿到的目标、资料、约束和历史反馈作出判断，Context 的质量直接影响它怎样理解问题、选择行动。开发过程中还需要实际执行和验证，把结果反馈给下一轮工作。Loop 将实现、检查、修订和经验积累连接起来，让上下文随着项目推进持续更新。

本项目中，我把主要精力放在这两部分：组织 AI 工作所需的 Context，设计开发与验收的 Loop，参与关键设计并确定取舍。Codex 在这个工作环境中承担方案推演、具体实现、测试执行和文档整理。

## 我如何组织 Context

- **筛选资料并研究问题。** 提供 Agent 架构、上下文、工具和工程实践等参考资料，结合题目讨论适用思路，明确哪些值得采用、哪些超出当前需要。
- **通过讨论对齐业务含义。** 梳理内容任务、业务简报、任务计划和内容活动方案，明确用户需要的成果、完成条件及各部分关系，让实现建立在共同理解上。
- **确定约束与工程原则。** 明确预算、截止、执行上限、版本、恢复和保存核实等要求；强调规则集中、interface 清楚、复杂度适度，并保留已有成果和过程记录。
- **把设计判断沉淀下来。** 通过讨论确认主 Agent 连续创作、Skill 提供方法、独立上下文核验、程序管理执行事实等分工，推动结论进入规格、工单、Skill 和项目文档，供后续实现继续使用。

## 我如何构建 Loop

开发按以下过程推进，验证结果再回到 Context，指导下一轮工作：

**资料研究与需求讨论 → 设计对齐 → 规格与工单 → 实现 → 自动测试和真实试用 → 反馈修订 → 验收收尾**

我的工作主要体现在：

1. **把验收标准前置。** 明确从公开 CLI、实际工具结果、持久产物、账本和保存文件判断完成，要求覆盖正常、缺输入、工具失败、预算超限和重复执行。
2. **组织不同层次的验证。** 用程序测试检查规则和流程，用真实模型运行观察决策与内容，用实际试用检查结果是否清楚、可读、可继续操作。真实与 Mock 的证据分别记录。
3. **根据反馈追问设计原因。** 真实运行暴露重复参数错误后，我提出工具使用前馈是否充分的问题，推动补齐用途说明、参数示例和错误反馈，再通过原始记录回放与真实任务检查调整后的表现。
4. **在关键节点作出取舍。** 参与比较设计方案、控制重构范围和返修投入，亲自运行 CLI、查看导出结果并提出呈现反馈，最终确定本轮结项和交付范围。

经过确认的结论与验证反馈继续沉淀到规则、代码、测试和文档中。后续迭代可以直接使用这些信息，减少重复解释和重复探索。

## AI 的实际使用范围

Codex 参与了资料与代码阅读、方案推演、源码和测试编写、命令执行、排错及文档整理。需求和设计通过讨论形成，由我确认关键取舍、验收标准和交付决定。

项目运行时，内容任务主 Agent 与评估 Agent 使用 DeepSeek，分别承担任务推进和内容核验。工具执行、资源计量、状态记录与保存核实由本地程序完成。

可执行检查和验证结果见[评估记录](03-evaluation.md)，实际模型输入、输出与工具往返见[提交样例](../examples/submission/README.md)。
