# 方案与设计

CLI 接收运营输入，以一条主循环推进任务。主 Agent 持有连续上下文，负责查证、创作、计划和返修；独立评估上下文核验完整方案；SQLite 保存任务事实。

```text
CLI：create / run / resume / inspect / export
                  │
                  ▼
主 Agent：目标、规则、创作 Skill、当前工作视图
                  │ 选择动作，观察结果
                  ▼
工具：资料检索、计划、估算、创作提交、核验、处置、保存
          │                 │
          ▼                 ▼
   SQLite 权威状态      有界内容核验
          │
          ▼
内容活动方案 + 执行报告 + JSON / JSONL Trace
```

## 主要职责

| 位置 | 职责 |
| --- | --- |
| `cli.py`、`service.py` | 创建、查询、显式更新、人工稿和资源采用 |
| `loop.py`、`prompts.py` | 模型循环、系统前馈、原生工具契约、当前状态 |
| `artifacts.py`、`campaign.py`、`task_plan.py` | 接收脚本、组装方案、记录任务计划 |
| `materials.py`、`knowledge.py` | 采用资料、Skill 正文和版本 |
| `review.py`、`evaluation.py`、`dispositions.py` | 独立核验、有限回读和意见处置 |
| `repository.py`、`db.py` | 输入、消息、产物、尝试、账本和保存事实 |
| `save.py`、`recovery.py`、`export.py` | 保存前提、中断核实和可读导出 |

模型接入使用 openai SDK 调用 DeepSeek，离线在同一接入位置注入预设响应。业务规则仍由同一套工具执行。依赖版本由 `uv.lock` 固定。
## 动态决策

主 Agent 每轮选择一个工具，观察实际返回后继续判断：资料不足时查证或澄清，预算与时间不够时调整剩余路径，核验提出问题时处置并返修，条件满足后保存。无可行路径时说明未完成原因，已有成果和消耗继续保留。

工具结果包含实际状态、版本、必要消耗和具体错误，后续动作依据这些信息展开。正常任务与预算停止的两条真实路径见 [评估记录](03-evaluation.md)。

## 设计取舍
### 保持一条创作主线

目标、受众、脚本、素材和制作安排相互影响，由主 Agent 连续处理，减少上下文交接。创作 Skill 提供方法；目标明确的内容核验使用独立上下文。

`submit_script` 接收完整脚本，首次可同时携带简报；`submit_campaign` 引用脚本版本并提交其余方案。程序校验并记录结果，模型继续依据回执行动。

### 让过程按实际需要展开

信息充分时直接创作，存在取舍时比较方向。任务计划在建立或实质调整工作安排时更新，关联已有成果和工具反馈。

返修明确要改的位置和应保留内容。脚本变化时提交关联旧稿的完整新版本，其余适用结果继续复用。可选改进根据收益、资源和回归风险决定是否投入。

### 把规则集中到程序

预算、模拟截止、版本适用性、执行上限和保存条件由程序核对。估算与实际执行采用同一适用费用表，模拟工具费、真实模型用量和制作投放费用分别记录。

工具契约说明用途、参数、前提和返回含义。错误反馈包含原因与定位，连续重复失败追加提醒，帮助模型修正下一次动作。

### 状态与版本随任务延续

SQLite 保存真实消息、输入、计划、资料、Skill、产物、核验和账本。新输入形成任务版本，新稿形成产物版本；资源更新可以保留适用成果，语义变化触发复核。

系统规则和工具定义保持稳定，采用变化与执行反馈向历史追加。恢复使用任务原采用的依据，轮数、费用和模拟进度继续累计。

### 核实交付

完整核验、关键意见处置、版本和资源满足条件后，由主 Agent 选择保存。程序核实文件与记录，明确区分成功、失败和结果未知。

模型提出内容判断，程序确认执行事实，运营决定方案采用。业务阅读和过程核对分别提供活动方案与执行报告。
