# 证据、协议与人工稿审查

基于集成提交 `58b72ac`，通过公开 CLI 和脚本化 Mock 模型验证；未调用真实业务模型。

## 发现和处理

- 采用新版资料后，旧脚本仍可用于提交新方案。红灯复现后，方案接收重新核对脚本证据的材料、版本和引文，不增加提交费用；返修后可提交。对已有方案直接复核同样有红灯：旧脚本或方案的版本化证据不再适用、简报引文不在新正文或材料缺失时，核验记录为未完成，不能保存。独立核验上下文包含当前资料版本、材料正文和范围。资源更新与显式采用不同，既有纯资源更新复用测试保持有效。
- 创作证据的 `scope` 非空并不保证范围真实。规格要求关联材料和适用范围，工具描述称校验范围，但创作字段没有约定必须是范围原文，设计示例也有概括；程序不能可靠地将自由文本语义比较为原文定位。当前程序仅校验非空，核验者收到证据和材料范围但未证明能识别错误；此项**未完成，待语义验收和明确可执行契约**。`propose_brief` 的工具说明现准确区分字段检查和语义核验，不代表问题已解决。驳回处置的材料依据不同：其工具明确要求范围原文片段，已有 `dispositions.py` 按材料范围定位，不以字面定位宣称主张语义正确。
- 非默认探针 `tests/scope_risk_probe.py` 使用材料明确为 iOS/Android 4.2 及以上，却提交“所有 iOS 和 Android 版本，包括 4.2 以下”。脚本化核验返回 pass 时，CLI 可保存完成，证明程序未独立拦截；Mock 是预设结果，既不能证明真实核验能捕获，也不能证明真实核验必然漏检。运行：`$env:PYTHONPATH='src'; python -m pytest tests/scope_risk_probe.py -q -o addopts=''`。
- 证据 ID `x] y` 的旧导出和人工未转义编辑可被误解析；原有基稿一致性检查在部分旧情况会拒绝，但不能覆盖所有情况。现对新导出编码标识和主张内分隔符，支持标点、空白、`无` 和实体样式 ID 的往返；歧义旧文件和未转义编辑安全拒绝，提示重新导出或使用 `&#93;`，不会修改原任务。空白控制字符按原值解码。已有合法数据无需修改；歧义旧导出文件须重新导出再编辑。
- handler 语义变化采用 `evidence-version-roundtrip-v1`；`save-redaction-review-v1` 任务指向旧代码 `3ceb16b`。公开 CLI 原有门禁已覆盖 update、adopt、import、run、resume、pause、review、save、reconcile 和 export（含 repair）；声称这些入口完全缺少门禁的报告不成立。回归从 `3ceb16b` 创建旧任务，逐入口检查拒绝、记录不变，status/inspect 可读；新建未初始化任务可正常更新。
- 同步修复集成分支发现的 Ruff 导入、未使用变量和测试表达问题；两项 unsafe 建议手工核对，只移除未使用赋值、将索引表达改为等价断言，未削弱业务断言。
