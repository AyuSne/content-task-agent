## 真实需求

实际动作计数来自主仓库 `examples/repair-live/`，摘录见 `real-action-counts.json`。12轮基线 `normal-initial-12` 的保留状态已用11轮，仅形成v1和7条核验意见，后续还需处置、必要返修、复审与保存。24轮任务 `normal-final-03`、`04`、`05` 分别达到3、2、3稿但均未保存，单项 `record_disposition` 实际占9、10、7个主动作。其余动作还包括检索、简报、比较/选择、生成、完整稿提交、核验及真实失败。不能把这些失败全部归因为模型能力或简单增加轮数。

新接口让同一评审的多条独立决定在一次请求中提交，减少逐条记录带来的无语义收益往返；它不合并意见依据、不降低质量要求，也不承诺下一次真实任务必能完成。默认上限保持24，旧任务额度及冻结工具协议不变。

## Interface与规则

主工具 `record_dispositions` 接受 `decisions` 数组，每项为 `finding_id`、`decision`、独立 `reason`。只接受当前采用产物的完整评审；每个ID必须属于该评审，批次内唯一，decision为 accepted/rejected/needs_evidence，reason非空。单次最多64条，且不超过本审finding数；任一非法，整批拒绝。全部校验通过后在一个事务中写入，纯本地意见记录不产生模拟费用。

已有 `record_disposition` 作为同一实现的一项调用，保留实际冻结任务所用的工具名与旧返回字段。参数校验、当前版本绑定和存储规则只维护一份。新任务主prompt仅修改第8条，优先一轮集中处置本审意见，版本升为 `main-2026-10-29.v10`；accepted仍需返修复审，rejected仍须原要求/证据。没有修改其它prompt规则、知识、Save或默认24轮配置。
