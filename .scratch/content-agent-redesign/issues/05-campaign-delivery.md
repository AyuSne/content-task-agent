# 05: 引用脚本形成完整方案并核验保存

**What to build:** 主Agent引用脚本版本提交其余方案内容，程序组装完整快照；独立核验取得全文，明确目标版本通过核验和保存后交付可核对文件。

**Blocked by:** [03：主Agent直接提交可引用的完整脚本版本](03-direct-script.md)

**Status:** completed

**Parent:** [内容任务规划Agent改造规格](../spec.md)

**User stories:** 17、18、19、20、21、36、46

## Acceptance criteria

- [x] 完整方案覆盖目标、受众、策略、内容安排、主脚本、素材用途/状态、制作步骤和必要未知，提交参数不重复脚本全文。
- [x] 方案固定引用提交时的脚本版本；之后出现新脚本不自动改写旧方案。
- [x] 核验与保存明确引用目标方案，程序检查任务归属及版本适用性，宿主管理调用ID和新版本编号。
- [x] 核验上下文包含完整快照、原始要求、适用证据及对应Skill，保留有界请求和有限只读材料回查。
- [x] 待制作或待获取素材有可执行路径时不被误判为必须已完成成片；本票不扩大到制作、投放或发布。
- [x] 只有核验完整、关键问题已处理、资源允许且全部交付文件核实后才报告完成；核验不完整、明确失败或未知分别反馈。
- [x] 通过正常无阻塞意见路径运行到核实保存，并从公开查询、运营成果和执行报告核对版本及分类成本。

## Scope

本票接通清晰的正常交付路径，复用已有核验与保存保障。需要返修或驳回意见的完整反馈分支由06承接；可以使用03已接通的独立简报路径，不以04为阻塞。

## Engineering and verification

以公开CLI、持久产物和状态/报告验收本票完整行为；本票实际使用的模型输入、工具反馈和适当测试随行为一起接通。复用现有真实/Mock seam，以小interface承载完整行为并集中规则；真实输入和外部交互处校验，内部依契约工作。保留必要的资源、版本、执行上限及核实保存要求，不引入假想adapter、静默兜底或双协议兼容层。旧测试按新行为调整，保留有效断言，真实与Mock证据分别说明。

前置票完成才进入实施前沿。具体提示词与字段按父规格契约细化；旧代码、历史资料、运行证据和未提交材料保留。
