# 09: 输入更新与人工稿进入新版本交付闭环

**What to build:** 运营更新输入或显式导入人工稿后，主Agent获得必要全文和变更事实，检查旧成果适用性，并将当前版本推进到核验保存或明确缺口。

**Blocked by:** [06：有据处置评审并完成返修复核闭环](06-review-revision.md)

**Status:** ready-for-agent

**Parent:** [内容任务规划Agent改造规格](../spec.md)

**User stories:** 03、05、37、38、39、42、43

## Acceptance criteria

- [ ] 纯资源更新与语义更新分别保留复用或失效依据，不清零已有消耗及执行上限。
- [ ] 人工稿显式关联基稿，形成待核验新产物，旧通过和处置不继承；过期基稿拒绝静默覆盖。
- [ ] 新协议的脚本引用和完整方案快照保持自洽，人工改动的接收不伪装成模型创作收费尝试。
- [ ] 主Agent得到必要的人工稿完整内容和输入变化，而不仅是一个未见正文的新版本号；保持现有无独立产物回读的范围。
- [ ] 未导入的外部编辑不成为权威内容，导出不一致如实说明，显式导入或修复各自保留事实。
- [ ] 通过正常CLI更新、导入、继续运行、核验与保存演示用户协作，并核对旧稿、旧意见和新版本之间的关系。

## Scope

本票验证正常协作后的下一次推进，不把08的执行中途崩溃机制作为前置；更新/人工稿与故障恢复的相邻能力组合在10覆盖。

## Engineering and verification

以公开CLI、持久产物和状态/报告验收本票完整行为；本票实际使用的模型输入、工具反馈和适当测试随行为一起接通。复用现有真实/Mock seam，以小interface承载完整行为并集中规则；真实输入和外部交互处校验，内部依契约工作。保留必要的资源、版本、执行上限及核实保存要求，不引入假想adapter、静默兜底或双协议兼容层。旧测试按新行为调整，保留有效断言，真实与Mock证据分别说明。

前置票完成才进入实施前沿。具体提示词与字段按父规格契约细化；旧代码、历史资料、运行证据和未提交材料保留。
