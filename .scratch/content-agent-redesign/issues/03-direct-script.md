# 03: 主Agent直接提交可引用的完整脚本版本

**What to build:** 主Agent使用适用简报，在同一上下文完成脚本并结构化提交；CLI能查到明确脚本版本、依据和实际消耗，返修可引用旧稿形成完整新版本。

**Blocked by:** [01：按任务采用版本估算与执行资源消耗](01-task-pricing.md)；[02：从标准Skill取得方法并跨进程复用](02-standard-skills.md)

**Status:** ready-for-agent

**Parent:** [内容任务规划Agent改造规格](../spec.md)

**User stories:** 01、02、04、05、06、07、08、09、13、14、16、32、45

## Acceptance criteria

- [ ] 保留输入校验和可选独立简报提交；事实、建议、假设、未知及其来源可以回查。
- [ ] 脚本提交内部不再调用创作模型；去除固定策略比较/选择登记和固定三候选依赖，方向与候选按任务需要处理。
- [ ] 接收完整脚本与适用简报引用，分配产物版本，校验材料支持、引用及资源并返回明确回执。
- [ ] 正式提交/返修按01的资源契约计量，拒绝与启动后失败区分，已有成果复用不收新的生成费。
- [ ] 返修引用旧脚本并提交完整新稿，旧版本保留，不受影响内容可核对。
- [ ] 同步主系统、创作Skill和已接通原生工具定义，保持单动作和真实调用历史；没有足够资料时沿已有澄清/停止通路保留成果。
- [ ] 建立新任务协议识别，明确旧任务固定旧代码及原采用资料的恢复入口；新程序对不适用旧任务给出具体说明，不建设双协议执行层。

## Scope

本票完成独立简报加脚本提交这一条可用路径；首次联合携带简报由04增加，完整方案交付由05承接。必要的产物规则集中在深module，不为每个工具添加浅包装。

## Engineering and verification

以公开CLI、持久产物和状态/报告验收本票完整行为；本票实际使用的模型输入、工具反馈和适当测试随行为一起接通。复用现有真实/Mock seam，以小interface承载完整行为并集中规则；真实输入和外部交互处校验，内部依契约工作。保留必要的资源、版本、执行上限及核实保存要求，不引入假想adapter、静默兜底或双协议兼容层。旧测试按新行为调整，保留有效断言，真实与Mock证据分别说明。
