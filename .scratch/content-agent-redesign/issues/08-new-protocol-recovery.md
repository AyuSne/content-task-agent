# 08: 新协议中断后准确恢复成果与消耗

**What to build:** 在联合提交、评审处置或保存等真实断点退出后，从新进程核实原任务并继续；有效产物、实际计划、知识、账本、时钟和执行上限一致延续。

**Blocked by:** [04：首次脚本提交可一并保存业务简报](04-joint-brief-script.md)；[06：有据处置评审并完成返修复核闭环](06-review-revision.md)；[07：主Agent维护可延续的实际任务计划](07-task-plan.md)

**Status:** ready-for-agent

**Parent:** [内容任务规划Agent改造规格](../spec.md)

**User stories:** 30、32、33、34、35、36、42、43、45、47

## Acceptance criteria

- [ ] 恢复实际原生调用及配对结果，采用正文/引用和产物版本不漂移，不使用旧计划或旧评审冒充当前成功。
- [ ] 对联合版本写入、批量处置及保存的关键中断点核实实际状态，不能仅根据预期把动作改记成功。
- [ ] 同次尝试和已有结果复用不重复执行或收费；真正的新业务尝试保留独立事实。
- [ ] 保存未知先核实，宿主已有reconcile责任继续生效，不新增模型核实工具或盲目重放。
- [ ] 暂停不推进模拟业务时钟，恢复、错误及非法响应后上限和已发生消耗不重置。
- [ ] 通过公开CLI子进程故障场景观察真实产物、回执、状态、报告及恢复后继续/停止结果。
- [ ] 旧任务通过固定旧代码和相应版本环境恢复，新程序不自动迁移或同时执行两套业务协议。

## Scope

04提供需核实的联合产物语义，06提供新评审/处置闭环，07提供需延续的实际计划；三个都是真实输入前提。输入更新和人工稿的正常协作路径由09负责，二者在10组合验证。

前置票完成才进入实施前沿。具体提示词与字段按父规格契约细化；旧代码、历史资料、运行证据和未提交材料保留。
