# 07: 主Agent维护可延续的实际任务计划

**What to build:** 主Agent可以建立和实质更新任务计划，CLI状态与执行视图显示真实步骤、依赖及成果/反馈关联，后续进程读到同一计划。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

**Parent:** [内容任务规划Agent改造规格](../spec.md)

**User stories:** 10、11、12、43、46

## Acceptance criteria

- [ ] 专用计划更新能力进入实际工具往返和持久任务记录，不仅修改展示文本。
- [ ] 计划可反映任务特有步骤及依赖，不再以固定四阶段投影充当整份计划。
- [ ] 只在建立或实质变化时调用，不要求每次业务动作前后另增一个回合。
- [ ] 步骤能够关联实际已有结果和反馈；计划完成标记不能授予内容核验、保存或任务完成资格。
- [ ] 使用当前已有任务和业务结果即可通过公开CLI演示计划建立、更新、正常跨进程读取及错误引用反馈。
- [ ] 保留计划更新的真实调用、单动作纪律和执行回合计数，不另收生成费。

## Scope

此能力不以新脚本或完整方案为成立前提，因此不人为依赖01至06。新稿变化后计划应怎样继续，由08至10的组合场景覆盖；不依赖新增产物回读工具。

## Engineering and verification

以公开CLI、持久产物和状态/报告验收本票完整行为；本票实际使用的模型输入、工具反馈和适当测试随行为一起接通。复用现有真实/Mock seam，以小interface承载完整行为并集中规则；真实输入和外部交互处校验，内部依契约工作。保留必要的资源、版本、执行上限及核实保存要求，不引入假想adapter、静默兜底或双协议兼容层。旧测试按新行为调整，保留有效断言，真实与Mock证据分别说明。

前置票完成才进入实施前沿。具体提示词与字段按父规格契约细化；旧代码、历史资料、运行证据和未提交材料保留。
