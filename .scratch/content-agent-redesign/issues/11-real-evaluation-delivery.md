# 11: 用真实模型和同场景对照交付改造证据

**What to build:** 维护者能够复现新协议正常、返修、澄清、受约束停止和恢复场景，审阅真实内容及完整成本，并在统一标准下比较固定旧基线和新实现。

**Blocked by:** [10：复杂历史中使用当前事实继续、澄清或停止](10-context-composition.md)

**Status:** ready-for-agent

**Parent:** [内容任务规划Agent改造规格](../spec.md)

**User stories:** 20、21、22、23、26、31、32、36、40、41、42、43、44、45、46、47、48

## Acceptance criteria

- [ ] 沿同一业务场景与评价标准进行新旧对照，补充Skill选择/引用、直接创作、完整返修、版本引用和有据驳回等新机制场景。
- [ ] 真实缺陷被错误驳回与误报被正确驳回分别评估；内容评价尽量隐藏新旧标签，核对位置、原始要求和材料支持，不以分数或形式字段代替语义判断。
- [ ] 记录整任务完成/正确停止、内容质量、请求和可得用量、墙钟耗时、返修/恢复开销、模拟消耗及可得缓存用量，未知金额仍为未知。
- [ ] 保留全部失败、标签纠正和原始结果；不把旧207项、11场景或18评审样例扩展为新协议证据，不要求每个场景调用都下降。
- [ ] 完成新协议的适当全量检查及固定范围代码审查，公开CLI、导出文件、账本和输入/产物版本能够互相核对。
- [ ] 更新可复制运行与证据说明，明确旧代码恢复入口、新旧协议范围、真实/Mock区别及已知限制；保留历史规格、工单和产物。
- [ ] 本票处理真实验证及交付说明，不新增真实制作投放、协作平台、自动学习、供应商路由或过度防御机制；运营采用及制作补问保留为已有入口的后续反馈，不假装已有数据。

## Scope

与实现相关的检查在各票进行，本票补齐真实语义与整任务对照证据，不是把所有有效验证推迟到最后，也不承诺未运行的效果。

## Engineering and verification

以公开CLI、持久产物和状态/报告验收本票完整行为；本票实际使用的模型输入、工具反馈和适当测试随行为一起接通。复用现有真实/Mock seam，以小interface承载完整行为并集中规则；真实输入和外部交互处校验，内部依契约工作。保留必要的资源、版本、执行上限及核实保存要求，不引入假想adapter、静默兜底或双协议兼容层。旧测试按新行为调整，保留有效断言，真实与Mock证据分别说明。

前置票完成才进入实施前沿。具体提示词与字段按父规格契约细化；旧代码、历史资料、运行证据和未提交材料保留。
