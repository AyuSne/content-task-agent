# 01: 按任务采用版本估算与执行资源消耗

**What to build:** 通过公开CLI创建任务、查看费用概览、按剩余动作估算并执行现有业务动作；切换环境默认价目后，原任务的估算、执行和报告仍使用其采用版本。

**Blocked by:** None (can start immediately)

**Status:** completed

**Parent:** [内容任务规划Agent改造规格](../spec.md)

**User stories:** 27、28、29、30、31

## Acceptance criteria

- [x] 集中选择适用费用表，能力概览、动作清单估算、执行前判断、实际消耗和报告不各维护一套价目。
- [x] 估算纳入已知必要核验、保存和选定返修；遗漏项给可行动反馈，清单不锁定后续顺序。
- [x] 公开查询可核对费用版本、单位、实际消耗和模拟进度；估算本身不冒充支出。
- [x] 执行前拒绝、启动后失败及结果复用遵循已有计量契约，为后续脚本提交提供同一资源行为入口。
- [x] 模拟工具费用、真实请求用量、制作投放估算分别记录，未知项保持未知。
- [x] 通过CLI场景证明环境默认价目变化不改变既有任务依据，预算不足或模拟截止不足时不启动对应业务尝试。

## Scope

本票先以现有可执行动作形成完整验证路径；正式脚本提交的操作条目在03接通时使用同一资源契约。费用数值来自适用版本表，不复制示例价目。

## Engineering and verification

以公开CLI、持久产物和状态/报告验收本票完整行为；本票实际使用的模型输入、工具反馈和适当测试随行为一起接通。复用现有真实/Mock seam，以小interface承载完整行为并集中规则；真实输入和外部交互处校验，内部依契约工作。保留必要的资源、版本、执行上限及核实保存要求，不引入假想adapter、静默兜底或双协议兼容层。旧测试按新行为调整，保留有效断言，真实与Mock证据分别说明。

前置票完成才进入实施前沿。具体提示词与字段按父规格契约细化；旧代码、历史资料、运行证据和未提交材料保留。
