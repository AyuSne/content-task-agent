# 04: 首次脚本提交可一并保存业务简报

**What to build:** 资料充分的任务无需先单独提交简报，主Agent一次提交简报和完整脚本，成功后得到两个关联版本；有无效部分时清楚知道整项未接收。

**Blocked by:** [03：主Agent直接提交可引用的完整脚本版本](03-direct-script.md)

**Status:** ready-for-agent

**Parent:** [内容任务规划Agent改造规格](../spec.md)

**User stories:** 13、15

## Acceptance criteria

- [ ] 独立简报仍可选，已有适用简报可引用，首次脚本允许携带新简报而不强制多一轮登记。
- [ ] 执行前整体校验，全部有效才启动业务尝试，成功时一并形成简报和脚本版本。
- [ ] 简报有效但脚本无效、或简报无效但脚本有效时均不形成其中任何新版本；保留真实调用并返回具体错误。
- [ ] 联合接收只有一次正式脚本业务尝试，简报不另收生成费；启动后失败和实际消耗按资源契约记录。
- [ ] 同一简报接收规则由所属module集中复用，避免独立和联合入口分别维护校验副本。
- [ ] 通过公开CLI运行和inspect核对成功、整项拒绝及修正后再提交的产物和账本。

## Scope

本票聚焦联合接收；执行中途崩溃和回执缺失的完整恢复组合由08验收。无需等待05，因为脚本与简报版本本身已可观察。

## Engineering and verification

以公开CLI、持久产物和状态/报告验收本票完整行为；本票实际使用的模型输入、工具反馈和适当测试随行为一起接通。复用现有真实/Mock seam，以小interface承载完整行为并集中规则；真实输入和外部交互处校验，内部依契约工作。保留必要的资源、版本、执行上限及核实保存要求，不引入假想adapter、静默兜底或双协议兼容层。旧测试按新行为调整，保留有效断言，真实与Mock证据分别说明。

前置票完成才进入实施前沿。具体提示词与字段按父规格契约细化；旧代码、历史资料、运行证据和未提交材料保留。
