# 06: 有据处置评审并完成返修复核闭环

**What to build:** 主Agent针对指定评审集中采纳或有据驳回意见，必要时提交完整脚本新稿和新方案再核验，最终保存适用版本或说明缺口。

**Blocked by:** [05：引用脚本形成完整方案并核验保存](05-campaign-delivery.md)

**Status:** completed

**Parent:** [内容任务规划Agent改造规格](../spec.md)

**User stories:** 04、16、18、20、21、22、23、24、25、26、32

## Acceptance criteria

- [x] 统一列表入口承接单条和多条处置，每项关联评审、意见、被审版本、决定、理由与必要依据。
- [x] 原始要求以输入版本、字段位置和原文定位，材料依据引用采用版本及片段；程序核对引用，语义支持由模型判断。
- [x] 整批先校验，全部有效才记录；任一无效时原处置状态保持，反馈指出具体位置和原因。
- [x] 真实必须修改的问题进入返修，误报允许有据驳回，可选意见按收益和剩余资源取舍；不强制每次驳回再加核验回合。
- [x] 脚本修改生成明确新版本，重组并核验新的完整方案；旧通过及旧处置不自动适用新稿。
- [x] 在公开CLI的受控反馈场景中，验证真实问题返修、误报驳回、错误引用拒绝和可选意见不强制重写。
- [x] 报告分别保留核验意见与主Agent处置，不用引用存在或已处理状态冒充语义质量保证。

## Scope

本票的Mock场景证明规则与反馈链路，不冒充真实模型的驳回质量证据；真实正反样例在11验证。

## Engineering and verification

以公开CLI、持久产物和状态/报告验收本票完整行为；本票实际使用的模型输入、工具反馈和适当测试随行为一起接通。复用现有真实/Mock seam，以小interface承载完整行为并集中规则；真实输入和外部交互处校验，内部依契约工作。保留必要的资源、版本、执行上限及核实保存要求，不引入假想adapter、静默兜底或双协议兼容层。旧测试按新行为调整，保留有效断言，真实与Mock证据分别说明。

前置票完成才进入实施前沿。具体提示词与字段按父规格契约细化；旧代码、历史资料、运行证据和未提交材料保留。
