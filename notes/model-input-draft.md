# 模型输入与工具调用草案

日期：2026-10-29（北京时间）。状态：interface与上下文组织草案，Q14至Q27的局部约定及Q28整体理解已确认，本轮设计讨论收束；具体字段仍待细化，尚未接入新实现。

后续修订遵循[项目设计原则](design-improvements.md#设计原则)，尤其核对工具interface的可理解性、反馈的可行动性及程序事实与模型判断的分工。

本文承接[主系统提示词草案](main-system-prompt-draft.md)，说明一次模型请求实际提供什么。依据当前产品源码、DSH一手源码、用户给定的commerce文章及DeepSeek官方Chat协议；系统正文是完整输入的一部分。

## 请求层：messages与tools各自承载什么

本产品使用openai SDK调用DeepSeek Chat Completions。[当前接入](../src/cta/model.py)明确分别传入 `messages` 和 `tools`；供应商内部如何将这些字段编码为模型输入不由本地实现决定。工具定义虽然是独立请求字段，仍属于模型上下文并产生输入成本。

| 内容 | 模型如何收到 | 维护责任 |
| --- | --- | --- |
| 常驻目标、共同工作及工具纪律 | `messages`中的system正文 | 主系统提示词 |
| 工具名称、用途/适用条件、参数含义与JSON结构 | 请求级 `tools[].function` 的 `name`、`description`、`parameters` | 工具定义；任务内固定内容与顺序 |
| 适用费用/耗时、单位、失败计量和采用版本 | 从适用费用表生成任务能力说明，进入带来源的消息；精确路径由成本工具计算 | 与执行共用的费用表和状态 |
| 当前任务、Skill目录、已预装标识、运行状态 | 以明确来源和适用范围的消息追加 | 宿主从持久事实组织 |
| 模型选择的调用与参数 | 模型回应中的assistant `tool_calls` | 实际模型回应，按原样持久化 |
| 实际执行结果和错误 | 关联调用ID的tool消息，进入后续历史 | 工具执行及返回渲染 |
| Skill正文和条件引用 | 模型加载时为工具结果；程序预装时为明确的宿主上下文 | 同一标准Skill载体及版本记录 |

当前首轮加载代码固定加入system正文、创作知识、任务输入和状态快照，没有单独预装完整工具费用表；具体估算及部分费用随工具反馈进入历史。[当前首轮装载及估算](../src/cta/loop.py)。新设计的任务能力说明是待实现的输入补充，不能描述为现有能力。

Q19已确认首轮随任务上下文提供小规模适用动作概览，包含费用、模拟耗时、单位、失败计量规则和费用表版本；后续追加变化和消耗状态。能力概览、剩余路径估算与实际执行共用同一适用表，模型不维护另一份价目来源。当前余额和时间属于动态事实，不持续写回固定system/tool description。

## Q14至Q16对模型输入的影响

已确认取舍以[改进记录D-01至D-03](design-improvements.md#d-01skill-载体与工具加载)为准。下表说明模型实际如何获得或提交相关内容；后续入口组织见下方工具集合，精确字段仍待细化。

| 场合 | 模型输入或输出 |
| --- | --- |
| 主Agent初始化 | 宿主明确预装创作Skill正文及其来源、版本和已加载状态 |
| 独立核验初始化 | 宿主为该上下文明确预装核验Skill正文及相同性质的来源记录 |
| 条件分支或其他适用Skill | 模型通过面向Skill的受限能力读取正文及引用资源，程序解析位置和任务采用版本；结果进入该Agent的实际历史 |
| 脚本返修 | 主Agent在工具参数中提交完整新脚本，并关联修订所依据的旧版本；后续完整方案引用新脚本版本 |

预装不自动展开全部引用资料，受限Skill读取不开放任意仓库文件访问。局部返修可只修改需要修改的内容，但本轮提交完整脚本，不采用修改补丁；完整方案提交继续复用明确脚本引用，避免重复输出。

## Q17至Q19对工具和上下文的影响

这些已确认选择的权威来源分别为[计划更新D-04](design-improvements.md#d-04按完成条件重审过程与上下文职责)、[费用能力D-07](design-improvements.md#d-07新创作提交的计量与版本一致性)和[对象版本D-08](design-improvements.md#d-08主系统提示词与内容分工)。具体名称、字段和展示格式仍需细化。

| 信息或行为 | 模型与宿主的职责 |
| --- | --- |
| 任务计划 | 主Agent通过专用工具在建立计划或实质变化时持久记录，关联成果和反馈；不要求每次业务动作前后另调一次计划工具 |
| 脚本与方案 | 模型选择宿主已提供的实际脚本版本，完整方案显式引用该版本 |
| 核验、保存与意见处置 | 模型分别明确引用目标方案，以及对应评审和意见；程序核对引用及结论适用性 |
| 任务归属与执行配置 | 宿主管理任务归属、实际调用ID、费用表版本及新版本编号，避免要求模型重复填写宿主已掌握的配置 |
| 行动消耗信息 | 首轮能力概览支持行动前理解，成本工具核算具体剩余清单，执行反馈提供实际消耗；三者共用适用费用表 |

计划的陈述不替代执行事实，对象引用不意味着核验或保存已完成。这些选择不把旧代码中的空参数核验/保存工具或固定阶段投影描述为已改造。

## Q20至Q21的引用与产物上下文

原始要求的定位方式见[已确认D-05](design-improvements.md#d-05内容选择与评审处置的有效性)。下面只示意字段语义，名称和编码仍为草案；输入版本、位置和原文也都是示意值：

```json
{
  "source_type": "task_input",
  "input_version": 3,
  "field_path": "requirements[1]",
  "quote": "需要在主视频中展示具体操作步骤"
}
```

引用使程序能够核对所指原文和适用版本，主Agent另说明该原文如何支持判断。材料依据引用材料版本及片段；定位成功仍不证明语义支持关系成立。

按[已确认D-02](design-improvements.md#d-02与现有上下文管理衔接)，本轮不增加独立产物回读工具。主Agent的创作正文沿实际assistant调用历史延续，恢复保留完整合法历史，人工稿导入及必要宿主内容注入提供相应正文。成功回执提供明确版本和必要变化，避免重复回显刚提交的整份内容。材料全文和Skill引用仍分别经对应读取能力取得；后续若出现产物正文的信息缺口或定位困难，再据此调整。

## 工具集合与字段草案

以下按Q1至Q27整理13项工具能力。Q22至Q25已确认入口合并、可选简报提交和旧策略工具退出，Q26、Q27补齐联合与批量接收语义；表中名称作为讨论名称使用，精确字段和JSON schema仍为草案。主模型的创作、比较和判断继续由主模型完成，表中提交能力负责接收及持久化结果。

| 工具名草案 | 模型表达什么 | 程序承担什么及关键返回 |
| --- | --- | --- |
| `read_skill` | Skill名称；读取引用时加相对资源位置 | 返回所采用版本的正文或引用内容及来源，限制在Skill资源内 |
| `search_materials` | 检索问题及适用检索方式 | 检索本任务材料，返回片段、来源、范围、缺口和实际消耗 |
| `read_material` | 本任务已有材料ID | 返回任务采用版本的完整原文及来源 |
| `estimate_cost` | 已知剩余动作清单 | 按适用表核算费用与模拟耗时，检查已知必要核验和保存是否纳入 |
| `update_plan` | 实际任务计划及其成果、反馈关联 | 在建立或实质变化时持久记录；计划陈述不代替执行事实 |
| `propose_brief` | 结构化业务简报 | 可选地单独保存事实、建议、假设、未知及其来源 |
| `submit_script` | 完整脚本；返修时引用旧版本；携带简报或引用适用简报 | 校验、登记业务尝试、按规则计量并保存版本，返回明确引用 |
| `submit_campaign` | 明确脚本版本及其余完整方案内容 | 组装并保存完整方案快照，返回版本及待核验事实，不重复回显已提交正文 |
| `review_campaign` | 目标方案版本 | 向独立核验提供完整快照、原始要求及证据，返回具体意见及版本、消耗、资料缺口 |
| `record_dispositions` | 对应评审及处置列表，每项含意见、决定、理由和必要依据 | 核对版本和引用、记录处置，单条使用单元素列表 |
| `save_campaign` | 目标方案版本 | 检查保存条件、执行保存并核实交付，返回成功、失败或未知事实 |
| `request_clarification` | 集中的问题、影响及是否阻塞 | 记录待补充事项并按约定暂停，保留有效成果和消耗 |
| `stop_incomplete` | 具体停止原因及缺口 | 如实记录未完成状态，不把普通文字或计划陈述当作完成 |

Q22、Q23已确认用一个`read_skill`同时读取入口正文和引用，用一个支持列表的`record_dispositions`承接单条或多条处置。Q25已确认旧`compare_strategies`及`choose_strategy`两个独立入口退出新集合；主Agent按需比较，在方案中说明方向与取舍，成本工具承担数值计算。Q27规定处置整批校验、全部有效才记录；有无效项时指出位置与原因，原处置状态保持。工具能力布局及接收语义已定不等于精确字段和运行行为已经完成。

Q24已确认业务简报保留为可回查依据，独立简报入口供确有需要时使用；信息充分时允许在首次脚本提交中一并持久化，已有适用简报则引用复用。Q26规定执行前整体校验、全部有效才启动业务尝试；成功时一并保存，校验失败不形成其中任一新产物版本，实际调用和具体错误保留。联合提交的精确字段仍待细化，启动后的失败和消耗沿用既有规则。

保存未知的核实仍由宿主恢复与reconcile职责承接，未核实前保持未知，不因列工具而新增独立核实入口。Q21下不新增产物回读工具；状态事实继续由宿主追加。上述宿主责任和必要内容注入不能因工具集合调整而遗漏。

核对主Agent究竟写出什么、程序返回什么及返修怎样引用版本时，读[创作提交与返修示例](creation-turn-draft.md)。该文展示完整示例脚本、上下文变化及已确认的接收语义；精确参数和示例费用仍是草案。

## 最小工具定义示意

以下用已有 `read_material` 展示原生字段，描述为草案措辞。其他工具遵循各自实际interface，不能只改系统提示词而继续暴露旧的固定策略、独立生成和三候选参数。

```json
{
  "type": "function",
  "function": {
    "name": "read_material",
    "description": "读取本任务已纳入材料的完整正文。用于核对引用、适用范围或片段冲突；返回正文、来源、范围或不可读原因。读取本身不收模拟工具费。",
    "parameters": {
      "type": "object",
      "properties": {
        "material_id": {
          "type": "string",
          "description": "本任务材料目录中的实际材料ID"
        }
      },
      "required": ["material_id"],
      "additionalProperties": false
    }
  }
}
```

description说明工具做什么、何时使用、必要前提和关键副作用/返回含义；parameters说明输入字段、类型、单位、版本引用及必填关系。跨工具的共同纪律可放稳定system段，复杂的业务组合方法由Skill提供。Python函数源码、宿主内部output校验器和文件路径不会因为存在于仓库就自动进入模型。

Chat的函数定义没有本项目可以任意添加的通用 `output_schema` 请求字段。若模型需要事前知道关键返回含义，应在简短description中说明；实际返回结构和结果在tool消息中提供。DSH内部的 `output.schema/render` 是宿主校验和渲染机制，不能直接当作本产品Chat请求字段照搬。

## 一次真实调用的往返

1. 宿主提交 `messages`、原生 `tools` 及调用配置。当前产品使用 `tool_choice="auto"`；系统要求每轮单动作不等于供应商自动保证恰好一个调用，宿主仍检查响应。
2. 模型回应assistant消息，选择工具并输出参数；函数由宿主执行。
3. 宿主校验工具名、参数、版本、资源和单动作要求，登记实际尝试，再执行并持久化结果。实际业务启动与费用遵循已确认计量规则。
4. 将原assistant调用和对应tool结果加入历史。拒绝、失败和未知结果同样如实关联调用ID。
5. 下一请求传回完整合法历史与同一组工具定义；模型依据实际返回选择下一步。

下面两条是消息格式示例，ID、版本和正文均为示意值，不是实测产物：

```json
[
  {
    "role": "assistant",
    "content": null,
    "tool_calls": [{
      "id": "call_example_1",
      "type": "function",
      "function": {
        "name": "read_material",
        "arguments": "{\"material_id\":\"M-001\"}"
      }
    }]
  },
  {
    "role": "tool",
    "tool_call_id": "call_example_1",
    "content": "{\"ok\":true,\"version\":\"materials-example\",\"material\":{\"material_id\":\"M-001\",\"source\":\"示意来源\",\"scope\":\"示意范围\",\"text\":\"示意正文\"}}"
  }
]
```

示例只解释真实调用的记录格式，不能用来伪造预装动作。程序预装Skill直接记录为有来源的上下文，不合成“模型曾调用”的assistant/tool配对。DeepSeek官方当前区分Chat与Messages/Responses的中途插入工具调用支持，借鉴DSH时保持本项目Chat协议。[官方工具调用指南](https://api-docs.deepseek.com/guides/tool_calls/)

## 工具结果也是上下文

成功结果返回下一步需要判断的事实、引用和版本；收费动作附实际尝试、费用/模拟耗时及必要资源事实。失败结果给出具体原因、已发生的副作用或消耗、当前缺口和有依据的可行动反馈。建议不能伪装成已执行事实，工具收到模型参数也不代表动作已经成功。

原始材料与完整日志用于追溯；模型侧返回任务相关字段，材料全文和Skill引用通过各自读取能力取得，产物正文沿Q21约定进入上下文。当前代码没有产物回读工具，新设计也不把通用回读作为本轮目标。外部材料内的指令按数据处理。新设计需评估真实输入大小、缓存用量和整任务效果，不能因工具字段独立于messages就称其免费，或直接套用Claude的缓存参数和命中率。
